# LearningSpace

A local study workspace for OpenCode. It keeps source material separate from
generated guides, uses a memory vault for durable context, and enforces output
quality with scripts and a Git pre-commit hook.

## Workflow

```text
input/  ->  StudyGuide/  ->  Flashcards/
input/ + relevant memory  ->  AssignmentGuide/
```

- Put `assignmentGoal.txt`, lecture decks, PDFs, and handouts in `input/`.
- Say **"generate assignment guide"** to build
  `AssignmentGuide/assignment-guide.md`.
- Say **"generate study guide"** to build `StudyGuide/study-guide.md` and its
  answer key.
- Say **"generate flashcards"** to build `Flashcards/flashcards.md` from the
  study guide.
- Treat `input/` as read-only source material.

## Folder map

```text
input/              source material for the current course set
AssignmentGuide/    assignment guide and tutor instructions
StudyGuide/         study guide and answer key
Flashcards/         flashcard deck
Memory/             Obsidian-compatible memory vault
scripts/            format, freshness, coverage, and release checks
template/           sanitized memory-vault skeleton
.githooks/          Git pre-commit hook
.opencode/          OpenCode project plugin and config
install.sh          interactive installer for end users
test-install.sh     safe installer smoke test
.guide-manifest.json  checksum manifest for generated outputs
LICENSE             MIT license
```

`dist/` is generated by the template builder and is not committed.

## Requirements

Tested with:

- OpenCode `v2.1.3`
- Git `2.56.0`
- Python `3.14.8`
- Glow `3.0.0` (optional, used for rendering checks)
- Obsidian (optional, for the `Memory/` vault)

Python 3 is required by the check scripts. Glow is optional; the script skips
the render check when Glow is not installed.

## Install

Run the installer from the workspace root:

```bash
./install.sh
```

The installer:

- asks where the project directory should live, defaulting to
  `~/LearningSpace`
- copies the workspace there when the target is different
- checks for Git, Python 3, and tar, and offers to install missing ones
- installs OpenCode 2 if `opencode` is missing
- prompts before installing optional Glow
- installs the bundled `memory-vault` OpenCode plugin
- initializes Git and enables the pre-commit hook when needed
- runs the guide, freshness, and source-coverage checks

It never overwrites a non-empty target directory.

Useful non-interactive options:

```bash
./install.sh --target ~/School/LearningSpace --yes
./install.sh --target ~/School/LearningSpace --yes --no-opencode --no-glow
./install.sh --target ~/School/LearningSpace --yes --skip-deps
```

Use `./install.sh --help` for the full option list.

### Provider setup

Installing OpenCode does not choose a model provider. After installation:

```bash
cd ~/LearningSpace
opencode
/connect
```

Use `/connect` to sign in or add the API key for the provider you want. Then
return to the workspace and start a session.

Obsidian is not installed by this script. Open `Memory/` as a vault, or replace
it with an equivalent vault that follows the standard below.

## Test the installer

Before running a full install, test it in an isolated temporary workspace:

```bash
./test-install.sh
```

The test:

- runs in a fresh directory under `/tmp/opencode`
- does not install OpenCode, Glow, or system packages
- copies the workspace
- initializes a temporary Git repository
- installs and runs the pre-commit hook
- confirms the source workspace was not modified
- deletes the temporary workspace when finished

To inspect the temporary copy afterward:

```bash
./test-install.sh --keep
```

## Build a shareable template

Do not distribute your personal workspace. Build a sanitized starter:

```bash
./scripts/build-template.sh
```

The default output is:

```text
dist/LearningSpace-template/
```

The builder removes personal input files, generated guides, session history,
project notes, `.obsidian` state, and Git history. It creates a clean memory
vault skeleton, keeps the installer and checks, and runs the template’s own
smoke test.

Override the output directory:

```bash
./scripts/build-template.sh /tmp/LearningSpace-template
```

## OpenCode setup

This section is OpenCode-specific. Other agent harnesses will not load
`AGENTS.md` or the memory plugin automatically.

### Instructions and routing

- `AGENTS.md` is the workspace router.
- Each working folder has its own `AGENTS.md`:
  - `input/AGENTS.md`
  - `AssignmentGuide/AGENTS.md`
  - `StudyGuide/AGENTS.md`
  - `Flashcards/AGENTS.md`
  - `Memory/AGENTS.md`
- `opencode.jsonc` loads the memory rules and vault home page into normal
  sessions:

```json
{
  "instructions": [
    "Memory/AGENTS.md",
    "Memory/Home.md"
  ]
}
```

- `StudyGuide/` and `Flashcards/` are intentionally memory-free.

### Plugins used

Only one custom OpenCode plugin is used:

**`memory-vault`**

- Source: `.opencode/plugins/memory/index.ts`
- Plugin ID: `memory-vault`
- Loaded automatically by OpenCode from `.opencode/plugins/`
- No npm install or external plugin package is required
- Uses OpenCode's plugin API and the current session model to summarize work

What it does:

- Runs after a successful top-level OpenCode session.
- Creates or updates a note in `Memory/04 Sessions/`.
- Links the note from `Memory/Home.md` and
  `Memory/04 Sessions/Sessions MOC.md`.
- Adds the session link to a matching project note under
  `Memory/03 Projects/` when one is found.
- Skips subagent sessions, other projects, `StudyGuide/`, and `Flashcards/`.
- Skips duplicate summaries instead of appending the same follow-up again.
- Uses a short idle delay, a cooldown, and a minimum-work check.

There are no external MCP servers configured in this workspace.

### Manual Git hook install

The main installer enables the hook. To do it manually:

```bash
scripts/install-hooks.sh
```

This sets:

```bash
git config core.hooksPath .githooks
```

The pre-commit hook runs:

```bash
scripts/check-guides.sh
scripts/check-stale.sh
scripts/check-coverage.sh
```

## Checks

### Formatting

`scripts/check-guides.sh` enforces the Glow-friendly layout used by the
assignment guide, study guide, answer key, and flashcards.

### Freshness

`.guide-manifest.json` records SHA-256 hashes of the input sources, generated
outputs, and output dependencies. This works across clones and copies where
file modification times are unreliable.

The normal command after generating or editing a guide is:

```bash
scripts/finalize-guides.sh
```

It runs the format and coverage checks, updates the manifest, and verifies that
the outputs are fresh. It refuses to update the manifest when source files
changed but no generated output changed, because that usually means the guides
were not regenerated.

For a manual check without updating the manifest:

```bash
scripts/check-guides.sh
scripts/check-stale.sh
scripts/check-coverage.sh
```

### Source coverage

`scripts/check-coverage.sh` verifies that:

- every lecture file in `input/` is represented in the study guide
- `assignmentGoal.txt` is represented in the assignment guide

## Memory vault standard

The plugin expects `Memory/` to be the Obsidian vault root by default and uses:

```text
Memory/
  AGENTS.md
  Home.md
  03 Projects/
  04 Sessions/
    Sessions MOC.md
  06 Templates/
    Session.md
```

An end user can replace `Memory/` with their own Obsidian vault, but it must
follow this standard for the plugin and links to work unchanged.

To use a different vault folder name, set `MEMORY_VAULT` before starting
OpenCode:

```bash
MEMORY_VAULT=MyVault opencode
```

Also update the two `Memory/...` entries in `opencode.jsonc` to point at that
vault.

The `.obsidian/` folder is user-specific app state and is not part of the
content standard.

## Reproducing the workspace

1. Clone or copy the workspace.
2. Run `./install.sh` and choose the project directory.
3. Replace the contents of `input/` with the current course source set.
4. Open OpenCode at the project directory and run `/connect`.
5. Run one of the generation prompts.
6. Finalize and run the checks:

```bash
scripts/finalize-guides.sh
```

7. Open `Memory/` as an Obsidian vault, or mount an equivalent vault.

## Windows and WSL

The installer is a Bash script and targets Linux, macOS, and WSL. On Windows,
use WSL and keep the project inside the WSL filesystem, such as
`~/LearningSpace`, rather than under `/mnt/c` for better performance.

## Version pinning

The installer defaults to the latest OpenCode 2 release. To pin a version:

```bash
OPENCODE_VERSION=2.1.3 ./install.sh
```

The workspace is tested with the versions listed under Requirements. Pin the
model and OpenCode version when reproducible output matters.

## Reproducibility limits

The folder layout, prompts, scripts, and Git hook are model-independent. The
content is not byte-for-byte reproducible across models: extraction, summary
wording, and ambiguous-source decisions depend on the model in use.

The checks enforce structure, freshness, and source coverage, not factual
accuracy or pedagogical quality. Review generated guides before relying on
them.
